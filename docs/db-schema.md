# Схема базы данных — описание таблиц

**Дата:** 15.11.2026
**СУБД:** PostgreSQL (Supabase)

---

## Общее

Три таблицы: `sources`, `events`, `summaries`.
Персональные данные не храним: полей с именами, email, телефонами и прочими контактами людей нет.

---

## Таблица `sources` — источники

Список адресов, за которыми следит сборщик. Хранится в базе, чтобы добавлять/удалять источники без правки программы.

| Поле | Описание |
|------|----------|
| `id` | Внутренний номер источника (порядковый, уникальный). Основной ключ. |
| `url` | Адрес источника. Уникальный — один и тот же адрес нельзя добавить дважды. |
| `title` | Название источника (для удобства чтения в списке). |
| `is_active` | Включён ли источник: да / нет. Выключенный сборщик не трогает. |
| `last_checked_at` | Когда сборщик последний раз обращался к источнику (успешно или нет). |
| `last_success_at` | Когда источник последний раз успешно ответил. |
| `error_streak` | Сколько ошибок подряд (0 = всё в порядке). Сбрасывается при успешном ответе. |

---

## Таблица `events` — события

Каждая строка = одно событие по материалу (реакция, новая статья, правка, попадание в подборку).

| Поле | Описание |
|------|----------|
| `id` | Внутренний номер события (порядковый, уникальный). Основной ключ. |
| `source_id` | Ссылка на источник, от которого пришло событие. |
| `material_url` | Ссылка на материал. **Уникальный ключ события** — одна и та же ссылка не порождает вторую строку при повторном прогоне. |
| `event_type` | Тип события: реакция / новая статья / правка / подборка. |
| `title` | Заголовок материала из ленты. Добавлен миграцией `003`. |
| `description` | Короткое описание материала (текст без разметки). Добавлен миграцией `003`. |
| `image_url` | Ссылка на изображение материала, если оно есть. Добавлен миграцией `003`. |
| `published_at` | Когда материал опубликован. Может быть пустым — не у всех источников есть эта дата. |
| `collected_at` | Когда сборщик увидел материал. Всегда заполняется. |

---

## Таблица `summaries` — сводки

Готовые сводки, которые уходят пользователю.

| Поле | Описание |
|------|----------|
| `id` | Внутренний номер сводки (порядковый, уникальный). Основной ключ. |
| `created_at` | Когда сводка сформирована. |
| `content` | Текст сводки (короткий, по делу). |
| `delivered_to_telegram` | Доставлена ли в Telegram: да / нет. |
| `delivered_to_email` | Доставлена ли на email: да / нет. |

---

## Связи между таблицами

- `events.source_id` → `sources.id` (каждое событие привязано к источнику).

Связь между `summaries` и `events` не заводим — сводка формируется по логике приложения (за период), а не жёсткой ссылкой в базе.
