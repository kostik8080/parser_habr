# parser_habr

Парсер-робот публичной активности статей на Хабре. Обходит RSS-ленту, складывает
события в Supabase (PostgreSQL) и в перспективе шлёт пользователю ежедневную
сводку в Telegram и email — чтобы не искать информацию по всему сайту.

Ниша: авторы по искусственному интеллекту, программированию и фронтенд-разработке
(подробности — в «Паспорт продукта.md»).

## Статус

**Работает:**

- Сбор RSS общей ленты Хабра (`https://habr.com/ru/rss/articles/`) → таблица `events`.
- Защита от дублей на уровне базы: уникальный `material_url`, повторный прогон
  обновляет существующие строки, а не создаёт копии.
- Нормализация ссылок: срезаются `utm_*`, `fbclid`, `gclid` и хвостовой слеш.
- Юнит-тесты чистой логики (сеть не трогают).

**В планах:**

- Таблица подписок (авторы, хабы, компании) и фильтрация на этапе сводки.
- Сводки за период и доставка в Telegram + email (ежедневно).
- Расписание запуска сборщика.
- События типа «реакции / правки / попадание в подборки» — RSS отдаёт только факт
  новой статьи.

## Структура

| Путь | Что это |
|------|---------|
| `collector.py` | Сборщик. Только стандартная библиотека Python, pip-зависимостей нет. |
| `db/` | Миграции PostgreSQL (Supabase), выполнять по номерам: `001` → `004`. |
| `docs/db-schema.md` | Описание таблиц: `sources`, `events`, `summaries`. |
| `Паспорт продукта.md` | Требования: события, исключения, доставка, критерий полезности. |
| `_test_collector.py` | Юнит-тесты (unittest из стандартной библиотеки). |

## Настройка

1. Создать проект в [Supabase](https://supabase.com) и выполнить миграции из `db/`
   по порядку в SQL Editor.
2. Скопировать `.env.example` в `.env` и заполнить значениями из
   Project Settings → API:

   ```
   SUPABASE_URL=https://<project>.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=<service_role key>
   ```

   Ключ `service_role` даёт полный доступ к базе. Хранить только в `.env` —
   файл исключён из git.
3. Запустить сборщик:

   ```
   python collector.py
   ```

   Python 3.10+, ничего устанавливать не нужно.
